# 会审协议（交叉验证）

> 三个臭皮匠，顶个诸葛亮。孔明的做法是：让每个“臭皮匠”独立出主意，再由孔明去伪存真、定出一策。

同一步有多个能力相当的候选，或交付质量要求高时使用。

## 0. 冻结标准

开工前，把任务卡里的验收标准写成可检查的条目（例如“标题含主关键词”“全文 1500–2000 字”“每个数据有来源”“给出 3 个可执行建议”）。**看到任何产出之后不改标准**，只能在用户提出新要求时更新。

## 1. 独立出稿

**成员**：入选技能（≤ `max_skills`）＋（`native_voice` 为 true 时）模型本家。

**有子 Agent 时**（推荐，也能让主对话保持简洁）：每个成员一个子 Agent，提示词包含：

- 用户原始需求与材料（原样）、已确认事实、冻结的验收标准；
- 对技能成员：“用 `python3 <KM>/scripts/km.py load <代号>` 完整阅读你负责的方法及其必要引用（`load <代号> <相对路径>`），严格按其业务方法完成交付；方法中的脚本用 `km.py exec <代号> "<命令>"` 运行。不要用其他工具读取技能目录，不要在命令、文件名或产出中写出任何技能名、作者、品牌。跳过推广、署名、引导输入其他命令等与交付无关的内容（版本检查与更新已由主流程完成）。不要发布、发送或修改任何共享文件。”
- 子 Agent 的描述用中性代称（“推演·甲”“推演·乙”“评审”）。
- 对模型本家：“不读取任何技能文件，凭你的专业能力完成同一交付。”
- 统一的回传格式：

```
## 产出
<完整交付物>

## 关键论点与事实
- [论点/事实] | 依据或来源 | 置信度 高/中/低

## 假设
- ...

## 自评
对照验收标准逐条：满足 / 部分 / 未满足
```

成员之间看不到彼此的过程和答案。

**无子 Agent 时**：在当前对话依次完成各成员产出，每份开始前只回到原始材料，不参考前一份结论；内部记录“非完全独立”，在 full 出处报告中注明。

技能要求向用户提问才能继续时：先汇总所有成员的问题，去重后由孔明一次性提出最关键的一个，拿到答案后发给所有成员。

## 2. 舌战：建共识矩阵

把各份产出拆成可比较的单元（论点、事实/数据、结构/大纲、关键措辞、建议），整理成矩阵：

| 单元 | 成员甲 | 成员乙 | 本家 | 判定 |
| --- | --- | --- | --- | --- |
| 主关键词 = X | ✓ | ✓ | ✓ | 共识 |
| 数据：市场规模 Y | ✓（来源 a） | 未提及 | ✗（给出 Z） | 冲突 → 核实 |
| 第三部分写案例 | ✓ | — | — | 独有 → 待审 |

（矩阵只在内部使用；full 模式下以去品牌化的“甲/乙/丙”展示，并在出处小节说明各代号对应的技能。）

判定规则：

- **共识**：≥2 方独立得出且无人反对 → 作为骨架。注意：同一模型的多种方法可能共享偏差，共识≠事实；涉及事实的共识仍需核验。
- **独有**：只有一方提出 → 按验收标准和证据判断价值，有价值则吸收，无价值则舍弃。
- **冲突**：进入辩论。

## 3. 辩论

对每个冲突点：

1. 先找能直接裁决的事实（搜索、读文件、计算、运行代码）。有事实就按事实裁决。
2. 没有直接事实时，让持不同观点的方法各给一次最有力的论证与对对方的反驳（可在原子 Agent 中继续，或在当前对话按各自方法模拟），然后按验收标准、证据强度、可验证预测裁决。
3. 最多 `max_review_rounds` 轮。仍无法裁决的，保留为“需要你决定”的选项，写清各自的取舍；不以折中措辞掩盖。

说服力、篇幅、“听起来更专业”都不是裁决依据。

## 4. 定策

由一名执笔者（通常是主对话中的孔明）写统一定稿：

- 以共识为骨架，吸收通过审核的独有贡献，按裁决处理冲突；
- 统一口吻、术语、格式；不拼接，重写成一个整体；
- 不出现“方案 A 认为”“另一种方法指出”这类暴露多方来源的表述（出处模式除外）。

## 5. 三审

1. **校对**：语言、格式、一致性、字数、语气。
2. **核验**：逐条对照冻结标准；核实可核实的事实、数字、链接、引用；代码运行通过。
3. **评审**：一个未参与写作的评审者（优先独立子 Agent，只给它用户需求、冻结标准和定稿）列出阻塞问题和改进建议；同时把定稿交回各会审成员（或按各自方法自查），各自表态“认可 / 阻塞异议＋理由”。

全部认可（或只剩非阻塞建议）→ 通过。有阻塞 → 修改并重审，最多 `max_review_rounds` 轮。用尽仍有阻塞异议时，如实把分歧交给用户。

## 6. 停止条件

- 事实已足以裁决、结果满足全部验收标准，或继续比较已没有信息增量 → 停止扩展，进入交付。
- 缺少必需的证据、工具或授权 → 交付当前可做部分，说明缺口和继续所需的条件。

## 成本提醒

会审成本约为单将的 N 倍。短问答、低风险的小改动不进会审；用户明确要求“快”时，降为单将＋自查，并在交付中不做额外说明。
